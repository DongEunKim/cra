# 용어 대응표 (eSync ↔ 우리 시스템)

각 사양서([10 PKI](10-PKI-사양서.md) · [20 프로비저닝](20-프로비저닝-사양서.md) · [30 OTA](30-OTA-시스템사양서.md)) 본문은 eSync 용어를 쓴다. 여기서 우리 시스템 용어와의 대응을 정리한다.
표제어별 항목이며, 상호 참조는 `[[표제어]]`로 잇는다.

---

## eSync Server

- **우리 용어:** 배포 플랫폼 (자체 OTA Platform)
- **뜻:** 캠페인·타겟팅, Component·Package DB, 서명, 감사를 담당하는 클라우드 백엔드. 인증기관이 아니라 [[CS Cert]]의 개인키로 서명하는 **서명자**이며, 디바이스 인증서의 **검증자**다.
- **관련:** [[eSync Client]] · [[Operator UI]] · [[GPDM]] · [[KMS]]

## eSync Client

- **우리 용어:** TGU (인스톨러)
- **뜻:** 장비의 게이트웨이 노드. 클라우드와 mTLS로 통신하고 업데이트를 오케스트레이션한다.
- **관련:** [[eSync Agent]] · [[eSync Server]]

## eSync Agent

- **우리 용어:** 업데이트 에이전트 (EPOS-10i의 경우 TGU에 동거)
- **뜻:** 서명 검증·플래시를 수행한다. EPOS-10i처럼 검증 능력이 없는 제어기에서는 TGU의 eSync Agent가 검증을 대행한다.
- **관련:** [[eSync Client]] · [[CS Cert]]

## OEM Root CA

- **우리 용어:** OEM Root CA
- **뜻:** 최상위 인증기관. 개인키는 오프라인 보관하며, 하위 인증기관 발급에만 쓴다. 각 제어기의 신뢰앵커(Root CA 공개키)의 출처다.
- **관련:** [[Device CA]] · [[Code Sign CA]]

## Device CA

- **우리 용어:** Dev-IC (디바이스 CA)
- **뜻:** 디바이스 인증서 발급기관. 개인키는 KMS에 보관한다. [[디바이스 인증서]]를 발급한다.
- **관련:** [[디바이스 인증서]] · [[OEM Root CA]]

## Code Sign CA

- **우리 용어:** CS-IC (코드서명 CA)
- **뜻:** 코드서명 인증서 발급기관. 개인키는 KMS에 보관한다. [[CS Cert]]를 발급한다.
- **관련:** [[CS Cert]] · [[OEM Root CA]]

## CS Cert

- **우리 용어:** 코드서명 리프 인증서
- **뜻:** Code Sign CA가 발급한 엔드엔티티(리프) 인증서. `EKU=codeSigning`. 그 개인키(KMS 보관)로 컴포넌트에 서명한다. 검증을 위해 컴포넌트에 동봉된다. 단수명으로 회전한다.
- **관련:** [[Code Sign CA]] · [[eSync Server]]

## 디바이스 인증서

- **우리 용어:** 부품 정품 인증서
- **뜻:** Device CA가 발급한 엔드엔티티 인증서. `CN=Serial`. mTLS에서 eSync Client의 신원을 증명한다. Tier-1 공정에서 발급되며 개인키는 제어기가 보관한다.
- **관련:** [[Device CA]] · [[eSync Client]]

## manifest.xml

- **우리 용어:** 설치 매니페스트
- **뜻:** 컴포넌트(ZIP) 안의 메타데이터 파일. 대상 노드·type·version·rollback·delta·SW 품번·HW 호환성을 담는다. 컴포넌트 전체가 서명되므로 매니페스트도 서명으로 보증된다.
- **관련:** [[Component / Package]] · [[호환성 정보 (HW)]] · [[SW 품번]]

## Component / Package

- **우리 용어:** 컴포넌트 / 패키지
- **뜻:** Component = 대상 엔드포인트(nodeName)용 버전형 소프트웨어 단위(`name`, `nodeName`, `type`, `versions`, 바이너리 `deltaSha`는 SHA-256). Package = Component 묶음(`components`, `componentRules`, `atomicRollback`). Campaign이 Package를 배포한다.
- **관련:** [[manifest.xml]] · [[Signed Component Database]]

## Signed Component Database

- **우리 용어:** 서명된 컴포넌트 저장소
- **뜻:** eSync Server가 서명을 마친 컴포넌트를 보관하는 저장소.
- **관련:** [[Component / Package]]

## Operator UI

- **우리 용어:** OTA 운영 플랫폼 (PS) · 운영 콘솔
- **뜻:** 캠페인·패키지·설치현황을 운영하는 단일 프론트엔드. RBAC로 딜러·AS에 부분 개방한다.
- **관련:** [[eSync Server]]

## GPDM

- **우리 용어:** HD건설기계 PLM
- **뜻:** SW와 SW BOM을 관리하는 PLM. Component·SW BOM의 출처 원장이자 유일 소스. GPDM에서 릴리스된 산출물만 eSync Server로 유입된다.
- **관련:** [[eSync Server]]

## KMS

- **우리 용어:** KMS (키 관리 시스템)
- **뜻:** 서명 개인키를 보관하는 시스템. 개인키는 밖으로 나오지 않으며, eSync Server의 서명 요청을 받아 KMS 안에서 서명한다.
- **관련:** [[CS Cert]] · [[eSync Server]]

## Insurance Kernel

- **우리 용어:** 복구 부트로더
- **뜻:** 제어기 보호 영역에 상주하는 최소 복구 코드. 플래시 실패로 애플리케이션이 손상돼도 재플래시할 수 있게 한다. 싱글뱅크 제어기의 복구 수단이다.
- **관련:** [[eSync Agent]]

## 호환성 정보 (HW)

- **우리 용어:** HW 호환성 (HW 모델·버전)
- **뜻:** 펌웨어가 적용 가능한 하드웨어 형상. manifest.xml에 담기며, eSync Agent가 UDS 0x22로 읽은 실측값과 대조해 호환성을 판정한다.
- **관련:** [[manifest.xml]] · [[SW 품번]]

## SW 품번

- **우리 용어:** SW 품번 (Part Number)
- **뜻:** 장비 옵션별 SW 변종을 식별하는 **구분자**. manifest.xml에 담기지만 호환성 판정 기준이 아니다. 어느 장비에 어느 품번을 적용할지는 VLM·정책으로 정한다(디바이스 자동 매칭 금지).
- **관련:** [[VLM]] · [[호환성 정보 (HW)]]

## UDS 서비스

- **우리 용어:** UDS on CAN (ISO 14229)
- **뜻:** `0x22`(ReadDataByIdentifier — HW ID 조회), `0x27`(SecurityAccess — 플래시 세션 게이트), `0x34/0x36/0x37`(RequestDownload/TransferData/RequestTransferExit — 플래시 전송). `0x29`(Authentication)는 EPOS-10i가 암호 능력이 없어 사용하지 않는다.
- **관련:** [[eSync Agent]]

## AWS IoT Core

- **우리 용어:** AWS IoT Core (연결점)
- **뜻:** eSync Server와 TGU를 잇는 통신 연결점. TGU와 mTLS로 연결하고, 시그널링(잡·MQTT)을 중계한다. 전송 담당 팀 소관.
- **관련:** [[eSync Client]] · [[JITP]]

## JITP

- **우리 용어:** Just-In-Time Provisioning
- **뜻:** TGU가 최초 접속할 때 AWS IoT Core가 Thing·인증서를 등록·활성화하는 절차. 인증서를 **발급**하는 것이 아니라(Device CA가 Tier-1에서 발급) **등록**한다.
- **관련:** [[디바이스 인증서]] · [[VLM]]

## VLM

- **우리 용어:** VLM (차량 레지스트리)
- **뜻:** 시리얼↔VIN↔장비 옵션 매핑과 SBOM 이력을 관리한다. 캠페인이 옵션별 [[SW 품번]] 변종을 타겟할 때 근거가 된다.
- **관련:** [[SW 품번]] · [[eSync Server]]

## 설치 정책

- **우리 용어:** InstallationPolicy
- **뜻:** 설치 시점·조건을 통제하는 정책. 시동 상태(ignition_off), 네트워크, 시간창 등을 지정한다.
- **관련:** [[eSync Client]]

## 신뢰 시각

- **우리 용어:** Trusted Time
- **뜻:** 인증서 유효기간·OCSP 검증에 필요한 신뢰 가능한 현재 시각. TGU가 소스를 보유해야 한다.
- **관련:** [[디바이스 인증서]]

## 델타

- **우리 용어:** Delta 업데이트
- **뜻:** 기준 버전과의 차분만 전달하는 업데이트. `manifest_diff.xml`과 기준 버전 참조를 포함하며, eSync Agent가 이미지를 재구성한다.
- **관련:** [[manifest.xml]] · [[Component / Package]]
