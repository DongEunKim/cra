> 판단·조문 인용은 컨설턴트가 수행하고, 사양설계자는 각 절차 사양의 **보안 속성**을 근거로 제공한다.

## 1. CRA 핵심 의무 ↔ 사양 매핑 (초안)

> 근거 문서 열은 현행 DOC-10/20 기준. Tier A 재계층(문서 지도) 진행 시 갱신한다.

| CRA 요구 영역 | 요구 요지 | 대응 아키텍처·메커니즘 | 근거 문서 | 상태 |
|---------------|-----------|------------------------|-----------|------|
| 보안 업데이트 제공 | 지원 기간 내 무료·적시 보안 업데이트 | FOTA 이중서명 배포·설치 | DOC-10 §1~3 | 🟡 부분 |
| 무결성·정품성 보증 | 변조·위조 방지 | 전자서명 PKI, Secure Boot | DOC-10 §1,5 / DOC-20 §4,6 | 🟡 부분 |
| 기밀성 보호 | 지적재산·데이터 보호 | Secure Flash(대칭키 암호화) | DOC-10 §4 | 🟡 부분 |

## 2. 미결 과제

- [ ] (컨설턴트) CRA 조문(Annex I 필수 요구사항, 취약점 처리 요구사항) 정확 인용·매핑
- [ ] 건설기계 제품군의 CRA 적용 범위·제품 분류 확정 (→ REF-01)
- [ ] 취약점 공개(CVD)·사고 신고(ENISA 통지) 프로세스 (→ REF-02)
- [ ] SBOM 생성·관리 방식 구체화 (VLM 연계)
- [ ] 지원 기간·보안 업데이트 정책 명문화 (→ REF-02)
- [ ] 갭 분석: 현 사양이 미충족하는 CRA 요구 식별
- [ ] **오프라인 타겟 인증서 폐기(revocation) 전략** — CS-IC·개발자 인증서 침해 시, 실시간 CRL/OCSP가 불가한 오프라인 제어기에서의 폐기·차단 방안(FOTA로 폐기목록 배포 + ARVN 연계). → [DOC-10 §1.3](../10-FOTA보안아키텍처/FOTA보안아키텍처명세서.md)

> ⚠️ 법률 자문 필요: 본 문서는 기술 대응 매핑이며, 규제 준수 판단은 법무·인증 검토를 거친다.
