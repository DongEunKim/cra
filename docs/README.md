# 문서 지도 (Master Document Map)

본 프로젝트 문서는 **두 계층(Tier)**으로 나뉜다. 저작 주체와 깊이가 다르다.

| | **Tier A — 사양(Specification)** | **Tier B — 참조/배경(Reference)** |
|--|--------------------------------|----------------------------------|
| 소관 | **본 프로젝트(사양설계자)** | **별도 CRA 컨설턴트** (설계자 인지용) |
| 깊이 | 구현 가능한 상세 설계 | 인지 수준(awareness) |
| 목적 | 만들 것을 규정 | 왜·무엇을 지켜야 하는지 이해 |

> **읽는 순서:** 참조-CRA배경(왜) → 아키텍처(토대) → 업데이트(구현) → 진단·생애주기(운영) → 추적성(증명).
> 이 순서에서 FOTA는 '업데이트 사양'의 하위 구현으로 자리하고, CRA는 앞머리 배경으로 얹힌다.

## 절차 사양 작성 원칙 (명사 / 동사 / 시간축)

구체적 절차(프로비저닝·서명·배포·업데이트·인증)가 흩어지면 개념이 파편화된다. 아래 원칙으로 배치한다.

- **정적(명사)** = 아키텍처(A1): CA 계층·인증서 프로파일·키·신뢰앵커·크립토. "무엇이 존재하는가."
- **동적(동사)** = 도메인 사양(A2/A3)의 절차: 시퀀스·입출력·검증. "누가 무엇을 어떤 순서로."
- **시간축** = 생애주기(A4)가 절차들을 순서대로 엮고 상세는 A2/A3로 위임.

### 생애주기 타임라인 ↔ 절차 배치

| 단계 | 절차 | 상세 집 | 정적 근거 |
|------|------|---------|-----------|
| ① 개발 | FW 생성·서명·배포 | A2 §생성·배포 | 서명 PKI(CS-IC)·패키지 모델 |
| ② 공정(부품사·EOL) | 프로비저닝(키생성·CSR·인증서/FW-Group-Key 주입·Factory Flashing·EOL 앵커) | A4 §공정 | PKI 계층·인증서 프로파일·키 |
| ③ 운영 | FW 업데이트·검증·설치 / 디바이스·라이선스 인증 | A2 §설치·검증 / A3 §인증 | 신뢰앵커·Secure Boot / 인증서 프로파일·Role OID |
| ④ 유지보수 | 부품교체(P&P)·키/인증서 회전·폐기·SBOM 갱신 | A4 §유지보수 | Anti-Rollback·폐기 전략 |

### 절차 사양 표준 템플릿

모든 절차는 같은 골격으로 기술하여 구현·감사·CRA 매핑을 쉽게 한다.

```
주체·신뢰경계 → 사전조건 → 입력물 → 단계 시퀀스(+시퀀스 다이어그램)
             → 산출물 → 검증(성공/실패 판정) → 예외·Fallback → 보안 속성(무엇을 보증)
```

> 마지막 **보안 속성**이 Tier B(REF-03 추적성)와 물리는 고리다. 각 절차가 어떤 CRA 요구를 만족시키는지
> 여기에 적어 두면 적합성 매핑이 자동으로 이어진다.
