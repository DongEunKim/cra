# 사이버보안 관리체계(CSMS · SUMS) 개요 (레퍼런스)

| **용어 기준** | [DOC-00 용어집](../00-공통/용어집.md) |

> CRA 요구의 **절반은 기술이 아니라 프로세스**(조직·역할·운영)다. 본 문서는 그 관리체계를 사양설계자가
> 이해하기 위한 요약이며, 실제 체계 수립·운영은 컨설턴트/거버넌스 조직 소관이다. 참고로 UNECE
> **R155(CSMS)**·**R156(SUMS)** 구조와 정합적으로 설계하면 추후 인증 확장에 유리하다.

---

## 1. 왜 관리체계가 필요한가

사양(Tier A)이 아무리 좋아도, **취약점을 언제·어떻게 처리하고, 업데이트를 어떤 정책으로 배포하며,
누가 책임지는가**가 없으면 CRA를 충족하지 못한다. 관리체계가 그 "운영 뼈대"다.

## 2. 구성 요소 (요지) 와 사양 접점

| 관리체계 요소 | 무엇 | 사양(Tier A) 접점 |
|---------------|------|-------------------|
| 취약점 처리(PSIRT) | 접수·분석·수정·배포·공개(CVD) | 업데이트 사양(FOTA 배포), 폐기 전략 |
| 보안 업데이트 정책(SUMS) | 지원 기간·배포 주기·강제 여부·롤백 정책 | 업데이트 사양, Anti-Rollback |
| 키·인증서 관리(KMS) | 발급·회전·폐기·보관 | PKI 아키텍처, Dev-IC/CS-IC/KMS |
| SBOM 관리 | 구성요소 수집·갱신·보관 | VLM·부품 이력 → REF-03 |
| 사고 대응·신고 | 탐지·대응·ENISA 통지 | 텔레매틱스 로그, VLM |
| 형상·이력 관리 | 장비별 SW/부품 이력 | VLM(개념적 추상 존재) |

## 3. 미도입 시스템과의 관계

- **VLM**은 이 관리체계의 '형상·이력' 축을 담을 유력 후보이나 **미도입·추상**(→ DOC-00 §2). 관리체계
  수립 시 VLM의 실체(레거시 통합 vs 신규 구축)를 함께 확정한다.
- **KMS**는 PKI 아키텍처와 관리체계가 공유하는 접점 → 사양(아키텍처)과 체계가 어긋나지 않게 조율 필요.
