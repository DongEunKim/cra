# doc-house-style — 문서 하우스 스타일

사내외 배포용 공식 문서라 형식이 일관돼야 신뢰가 간다. 이 프로젝트의 문서들이 이미 공유하는 규약을
아래에 정리한다. 새로 쓰거나 고칠 때 이 형식을 따른다. 기준 파일: [CLAUDE.md](../../../CLAUDE.md),
[docs/README.md](../../../docs/README.md).

## 문서 식별·번호

- 문서는 `DOC-NN`으로 식별한다: DOC-00 용어집 / DOC-10 FOTA / DOC-20 PKI·UDS / DOC-30 CRA.
- 폴더 접두 번호(00/10/20/30)로 순서를 고정한다. 새 문서는 빈 십의 자리를 쓴다.

## 명세서 상단 메타 블록

각 명세서 본문(`*명세서.md`)은 제목 다음에 메타 표를 둔다:

```markdown
# <문서 제목>

| 항목 | 내용 |
|------|------|
| **문서 ID** | DOC-NN |
| **문서 버전** | vX.Y (근거/원본) |
| **문서 분류** | 보안 아키텍처 / 기술 명세서 |
| **적용 대상** | <주체들> |
| **용어 기준** | [DOC-00 용어집](../00-공통/용어집.md) |

<한두 문장 요지>

---
```

## 절 번호와 상호참조

- 절은 `## N.`, 하위는 `### N.M`. 본문에서 가리킬 때는 `§N.M`.
- **문서 간** 참조는 `DOC-10 §3.2`처럼 문서 ID + 절 번호. 가능하면 Markdown 링크를 건다.
  예: `(→ [DOC-00 §0.2](../00-공통/용어집.md))`.
- **문서 내** 참조는 `§5.2`로 짧게.
- 파일/자산 참조는 상대경로 링크. 다이어그램은 `assets/diagrams/…svg`.

## 마커 규약

의사결정 상태를 한눈에 보이게 한다. 독자와 후속 작업자가 "무엇이 열려 있는지" 바로 안다.

| 마커 | 뜻 |
|------|-----|
| `> ✅ **[확정]** …` | 결정됨 (근거 포함) |
| `> ⚠️ **[미결 · 대화로 확정]** …` | 아직 안 정함 |
| `TODO:` / `(후속)` | 후속 정제 과제 |
| `TBD` | 미정 값 (DOC-00 §5 추적표에도 등록) |
| `> **근거(…):** …` | 설계 결정의 이유 (특히 CRA 관련은 근거를 반드시 남긴다) |

## 표현 형식

- **표**: 비교·매핑·프로파일은 표로. 헤더는 `**굵게**` 라벨 열을 왼쪽에.
- **패키지 트리**: 코드펜스 안에 `📦📂📜📄🔐📦` 이모지 트리. 각 항목 아래 `* 목적:`/`* 예외:` 주석.
- **노트 블록**: 참고·경고·근거는 `>` 인용. 제목은 `> **[참고] …**`.
- **인라인 코드**: 식별자·파일·값·OID·알고리즘은 백틱. (예: `CS-IC`, `.der`, `AES-256-GCM`, `0x29`)

## 개정 이력 (문서 하단 필수)

의미 있는 변경마다 한 줄 추가한다. 무엇을·왜 바꿨는지가 드러나야 한다.

```markdown
## 개정 이력

| 버전 | 일자 | 내용 |
|------|------|------|
| v1.0 | YYYY-MM-DD | 최초 정제 … |
| v1.1 | YYYY-MM-DD | **용어 검수 반영:** … |
```

- 날짜는 절대일자(YYYY-MM-DD). 버전은 문서별 독립(DOC-10 v1.x, DOC-20 v1.x …).
- 편집 후에는 **해당 문서 폴더 README의 상태/TODO 체크박스도** 함께 갱신한다.

## 관련 문서 링크 (문서 하단)

개정 이력 다음에 `## 관련 문서` 섹션으로 DOC-00 및 형제 문서를 링크한다.

## 언어·톤

한국어. 공식 명세 톤(단정은 근거와 함께, 미확정은 솔직하게 표시). 약어는 최초 등장 시 풀어쓴다
(용어는 term-guard/DOC-00 기준).

## git

의미 단위로 커밋한다. 메시지는 `docs(DOC-NN): <요지>` 형태, 본문에 무엇을·왜. 커밋·푸시는 사용자가
요청할 때만.
