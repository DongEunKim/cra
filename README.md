# CRA 대응 보안 기술문서 프로젝트

건설기계 제어기의 **소프트웨어 업데이트(OTA·유선)** 와 **PKI·진단(UDS 0x29) 보안**을
Excelfore **eSync** 기반으로 정의하고, **EU 사이버 복원력 법안(Cyber Resilience Act, CRA)** 요구사항에
대응하기 위한 사양 문서 프로젝트이다.

## 문서 원본 방침 (Docs-as-Code)

- **원본(Source of Truth):** `spec/`의 Markdown.
- **다이어그램:** `spec/assets/`의 자기완결 SVG.
- **근거:** `eSync/`의 eSync 공식 자료·외부 표준. 내부 문서는 상호 근거로 쓰지 않는다.
- **버전관리:** git — 모든 변경을 커밋 이력으로 추적한다(CRA 추적성 요건 부합).
- **언어:** 한국어. 용어는 [spec/00-용어집.md](spec/00-용어집.md) 기준으로 통일한다.

> 배포용 HTML/PDF는 Markdown 원본에서 파생 생성한다(빌드 파이프라인 추후 구성).

## 디렉토리 구조

```

│   ├── README.md          #   문서 지도 (공통 / 제어기별)
│   ├── 00-용어집.md
│   ├── 10-PKI-사양서.md
│   ├── 20-프로비저닝-사양서.md
│   ├── 30-eSync-OTA-공통아키텍처.md
│   ├── 31-EPOS-10i-OTA사양서.md
│   ├── 32-EPOS-30i-업데이트-사양서.md
│   ├── 40-유선업데이트-사양서.md
│   └── assets/            #   SVG 다이어그램 (자기완결)
├── eSync/                 # eSync 공식 참조자료 (근거). 기밀 원문 일부는 git 제외
```

> `.claude/`(프로젝트 로컬 스킬·에이전트)와 `CLAUDE.md`(작업 가이드)는 로컬 도구 설정이라 git 추적에서 제외한다.

## 문서 체계

사양은 **공통 계층**(모든 제어기 적용)과 **제어기별 계층**(능력별 변주)으로 나뉜다.
전체 구조·읽는 순서는 [spec/README.md 문서 지도](spec/README.md)를 따른다.

| 계층 | 문서 | 경로 |
|------|------|------|
| 공통 | 00 용어집 | [spec/00-용어집.md](spec/00-용어집.md) |
| 공통 | 10 PKI 사양서 | [spec/10-PKI-사양서.md](spec/10-PKI-사양서.md) |
| 공통 | 20 프로비저닝 사양서 | [spec/20-프로비저닝-사양서.md](spec/20-프로비저닝-사양서.md) |
| 공통 | 30 eSync OTA 공통 아키텍처 | [spec/30-eSync-OTA-공통아키텍처.md](spec/30-eSync-OTA-공통아키텍처.md) |
| 공통 | 40 유선 업데이트 사양서 | [spec/40-유선업데이트-사양서.md](spec/40-유선업데이트-사양서.md) |
| 제어기 | 31 EPOS-10i OTA 사양서 | [spec/31-EPOS-10i-OTA사양서.md](spec/31-EPOS-10i-OTA사양서.md) |
| 제어기 | 32 EPOS-30i 업데이트 사양서 | [spec/32-EPOS-30i-업데이트-사양서.md](spec/32-EPOS-30i-업데이트-사양서.md) |

- **공통 30**은 제어기 무관한 아키텍처·워크플로·서명·전송·타겟팅·정책·감사를 정의한다.
- **제어기별 31·32**는 30을 상속해 능력별 변주(HSM 유무·검증 위치·페이로드·뱅크·세션)를 다룬다. 이후 제어기는 33·34…로 추가한다.

## 상태

- 공통(00/10/20/30/40) 및 제어기별(31 EPOS-10i, 32 EPOS-30i) 사양 초안(Draft) 작성 완료.
- 구 `docs/`(초기 Tier A/B 문서)와 구 다이어그램은 `legacy/`로 아카이빙했다.
- CRA 조항 매핑, 배포 빌드 파이프라인은 후속 과제.
